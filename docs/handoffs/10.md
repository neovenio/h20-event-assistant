# Handoff: #10 Rate-limit / abuse-protect the public n8n webhook (Gemini cost exposure)

> Superseded in part by #46 (`docs/handoffs/46.md`, `docs/adr/0007-rate-limit-hits.md`): `checkRateLimit`, the `ratelimit:*` rows and the `Rate limit payload` / `Record rate limit` / `After rate limit` / `Rate limit recorded` nodes described below were replaced by insert-first `ratehit` rows, which are race-safe. The limits and the sign-in gate are unchanged.

## What changed

- **Firebase sign-in required for live AI actions**:
  - `backend/n8n/generate-workflows.cjs` (Workflow B `Access` node): only `action === 'catalogue'` takes the `'public'` branch (`request.body?.action !== 'catalogue' ? 'verify' : 'public'`). Unauthenticated calls to `chat`, `event-request`, `my-requests`, or `lookup` are rejected with HTTP `401` before reading `h20_records` or calling Gemini.
  - `backend/n8n/code/domain.cjs` (`publicAction`): defense-in-depth `401` check (`Log eerst in om de AI-assistent te gebruiken.`) on `chat` when `_identity.uid` is absent.
  - `src/app/event-assistant/n8n-client.ts`: attaches `Authorization: Bearer <idToken>` on all actions except `catalogue` (including `chat`).
- **Privacy-preserving per-IP & global hourly rate limits in the Data Table**:
  - `backend/n8n/code/auth-context.cjs`: pure-JS SHA-256 (`sha256`, `hashClientKey`, `clientKeyFromHeaders`) extracts the caller IP from `x-forwarded-for` (first entry), `cf-connecting-ip`, or `x-real-ip` and hashes it to `sha256:<64-hex>` inside the restricted n8n Code VM sandbox without `require('crypto')`. Raw IP addresses are never stored in `h20_records` (GDPR-compliant).
  - `backend/n8n/code/domain.cjs`: exports `RATE_LIMITS` and `checkRateLimit(rows, action, clientKey, nowMs)` enforcing a rolling 1-hour (`3600_000` ms) window pruned on every write:
    - `chat`: max **20** per client/IP per hour, max **120** global per hour.
    - `event-request`: max **5** per client/IP per hour, max **30** global per hour.
    - Exceeding either limit returns HTTP `429` (`Te veel verzoeken. Probeer het over enkele minuten opnieuw.`) without calling Gemini or inserting a claim row.
    - Idempotent retries of an already-held `event-request` (`requestId` + `customerToken`) are checked **before** `checkRateLimit` so receipt retries still return `200` even when the caller's quota is full.
    - `settleClaim` re-checks `checkRateLimit` against the fresh Data Table read after slot claim insertion (and deletes its own claim row on `429` if concurrent requests raced).
    - `adminAction('snapshot')` ignores `kind: 'ratelimit'` rows so they never pollute catalogue, bookings, blocks, or audit logs.
  - `backend/n8n/generate-workflows.cjs`: inserts `Rate limit payload` → `Record rate limit` (Data Table `upsert` on `ratelimit:<action>`) → `After rate limit` → `Rate limit recorded` between `Needs Gemini` and `Gemini` in Workflow B, failing closed with `503` if the Data Table write fails.
- **Frontend live-chat login gate**:
  - `src/app/event-assistant/components/assistant.ts` & `src/app/app.html`: `Assistant` injects `AuthService` and exposes `(requestLogin)`. When `store.live()` is true and `!auth.user()`, it displays `'Log in met je H20-account om met de live AI-assistent te chatten.'`, disables chat input/chips/submit, and offers `'Inloggen om te chatten'` wired to open the login modal (`login = true; chat = false`). Local demo mode (`!store.live()`) continues to work without signing in.

## Google Cloud Gemini quota cap & billing budget checklist (manual ops step)

Before opening `/webhook/h20/public` to broad traffic, apply these hard Google Cloud caps on the GCP project owning the n8n Gemini API key:

1. **Restrict API key scope** (`Google Cloud Console → APIs & Services → Credentials`):
   - Edit the Gemini API key used in n8n's `x-goog-api-key` Header Auth credential.
   - Set **API restrictions → Restrict key → Generative Language API** (`generativelanguage.googleapis.com`).
2. **Lower Generative Language API quotas** (`Google Cloud Console → IAM & Admin → Quotas & System Limits`):
   - Filter by service `generativelanguage.googleapis.com`.
   - Cap **GenerateContent request limit per minute** (e.g. `15` RPM) and **GenerateContent request limit per day** (e.g. `500` RPD in prod, `100` RPD in dev).
3. **Create a Billing Budget & Alerts** (`Google Cloud Console → Billing → Budgets & alerts`):
   - Create a monthly budget scoped to the H20 project and **Generative Language API** (e.g. `€15`/mo dev, `€50`/mo prod).
   - Enable email alerts at **50%**, **80%**, and **100%** of actual and forecasted spend.
4. **Re-import Workflow B in n8n**:
   - Import `backend/n8n/workflows/B-public-api-and-proposals.json` and select the `h20_records` Data Table in `Read records`, `Insert claim`, `Re-read records after claim`, `Delete lost claim`, `Record rate limit`, and `Save record`.
