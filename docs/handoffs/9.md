# Handoff & Runbook: #9 Production Firebase & n8n setup (`h20-event-assistant-prod`)

## Architectural decision

Production data, identity verification, rate limits, and email notifications are isolated from development per [`docs/adr/0004-prod-n8n-separation.md`](../adr/0004-prod-n8n-separation.md):

- Dedicated n8n Data Table: `h20_records_prod` (`recordId`, `kind`, `payload` String columns).
- Separate `[PROD]` workflow imports (A–D) in `neovenio.app.n8n.cloud` with webhook paths `h20-prod/public` and `h20-prod/admin`.
- `Verify Firebase token` bound to the `h20-event-assistant-prod` web API key and CORS restricted to `https://h20-event-assistant-prod.web.app` (plus any custom H20 production domain).

## Step-by-step production setup checklist

### 1. Firebase Console (`h20-event-assistant-prod`)

- [ ] Open the Firebase Console for project **`h20-event-assistant-prod`**.
- [ ] Under **Project settings → General → Your apps**, register a **Web app** (e.g. `H20 Event Assistant Prod`) and copy its public `firebaseConfig` (`apiKey`, `appId`, `messagingSenderId`, `projectId`, `authDomain`, `storageBucket`).
- [ ] Under **Authentication → Sign-in method**, enable **Email/Password** (keep Email link / passwordless disabled unless needed).
- [ ] Under **Authentication → Settings → Authorized domains**, confirm `h20-event-assistant-prod.web.app`, `h20-event-assistant-prod.firebaseapp.com`, and any custom H20 domain are listed (remove `localhost` in production if desired after verification).

### 2. Populate `config/runtime/prod.json`

Update `config/runtime/prod.json` with the public web config values from Step 1 and the isolated `[PROD]` webhook base URL (never put secret keys or service account JSON here):

```json
{
  "n8nWebhookBaseUrl": "https://neovenio.app.n8n.cloud/webhook/h20-prod",
  "firebase": {
    "projectId": "h20-event-assistant-prod",
    "appId": "<PROD_FIREBASE_APP_ID>",
    "storageBucket": "h20-event-assistant-prod.firebasestorage.app",
    "apiKey": "<PROD_FIREBASE_WEB_API_KEY>",
    "authDomain": "h20-event-assistant-prod.firebaseapp.com",
    "messagingSenderId": "<PROD_MESSAGING_SENDER_ID>"
  }
}
```

Verify locally with standalone commands:

```bash
npm run test:config
node scripts/write-runtime-config.cjs prod /tmp/h20-prod-runtime-check
```

### 3. Isolated `[PROD]` n8n Data Table & Workflows (`docs/adr/0004-prod-n8n-separation.md`)

- [ ] Create Data Table **`h20_records_prod`** in `neovenio.app.n8n.cloud` with three **String** columns: `recordId`, `kind`, `payload`.
- [ ] Import `backend/n8n/workflows/A-official-website-scraper.json`, `B-public-api-and-proposals.json`, `C-employee-api.json`, and `D-email-notifications.json` as separate workflows prefixed with **`[PROD]`**.
- [ ] In every Data Table node across `[PROD]` A–D, select **`h20_records_prod`**.
- [ ] In **`[PROD]` B** and **`[PROD]` C**:
  - Change Webhook paths to `h20-prod/public` (`[PROD]` B) and `h20-prod/admin` (`[PROD]` C).
  - Update **Verify Firebase token** URL `key=` parameter to `<PROD_FIREBASE_WEB_API_KEY>` from `h20-event-assistant-prod`.
  - Restrict **Allowed Origins (CORS)** to `https://h20-event-assistant-prod.web.app` (plus any custom H20 production domain; omit `http://localhost:4200` and dev Hosting).
- [ ] In **`[PROD]` B**, attach the Gemini Header Auth credential (`x-goog-api-key`).
- [ ] Run **`[PROD]` A** manually to stage official sources in `h20_records_prod`, then publish **`[PROD]` B** and **`[PROD]` C**.
- [ ] Configure **`[PROD]` D** per [`docs/handoffs/11.md`](./11.md) with `FRONTEND_ORIGIN = 'https://h20-event-assistant-prod.web.app'`.

### 4. Grant `staff: true` to real H20 staff accounts

After H20 staff create their accounts in `h20-event-assistant-prod`, run `scripts/staff-claim.cjs` locally using administrator ADC credentials:

```bash
gcloud auth application-default login
node scripts/staff-claim.cjs --project h20-event-assistant-prod --email <medewerker@h20.gg> --grant
node scripts/staff-claim.cjs --project h20-event-assistant-prod --email <medewerker@h20.gg> --show
```

To revoke access immediately (also revokes refresh tokens):

```bash
node scripts/staff-claim.cjs --project h20-event-assistant-prod --email <medewerker@h20.gg> --revoke
```

### 5. GitHub `production` environment & `main` branch protection

- [ ] In GitHub `neovenio/h20-event-assistant` → **Settings → Environments → `production`**:
  - Confirm secret **`FIREBASE_SERVICE_ACCOUNT`** contains a valid GCP service account JSON with Firebase Hosting deploy permissions on **`h20-event-assistant-prod`** (not dev).
  - Optionally enable **Required reviewers** on the `production` environment so merges to `main` require explicit release sign-off before `deploy-prod` runs.
- [ ] Under **Settings → Branches**, protect **`main`**:
  - Require pull request before merging.
  - Require status checks to pass (`code-quality`, `test`, `build` from `.github/workflows/ci-cd.yml`).
  - Block force-pushes.
