## Step-by-step live verification runbook

### 1. Grant dev staff claim (`#5`)

Authenticate locally with Google Cloud ADC for `h20-event-assistant-dev` (never commit keys), then grant `staff: true`:

```bash
gcloud auth application-default login
node scripts/staff-claim.cjs --project h20-event-assistant-dev --email <staff-test-email> --grant
node scripts/staff-claim.cjs --project h20-event-assistant-dev --email <staff-test-email> --show
```

Sign out and back in as `<staff-test-email>` in the app (`http://localhost:4200` or `https://h20-event-assistant-dev.web.app`) so the refreshed Firebase ID token carries `staff: true`.

### 2. Customer → Gemini proposal → staff approval happy path

- [ ] **Customer request submission:** Sign up / sign in with a non-staff customer test account, build an event in `/plan`, submit with test contact details, and confirm a receipt reference (`H20-...`) and personal `#request=<uuid>&token=<token>` URL are returned.
- [ ] **Data Table inspection (`h20_records`):** Confirm `booking:<uuid>` has `claimStatus: "held"`, `requestStatus: "pending_review"`, a Dutch `explanation`, and a structured `planning` array using only selected rooms.
- [ ] **Pre-approval privacy gate:** Open the personal receipt link as the customer (and inspect the `/webhook/h20/public` `lookup` network response). Confirm `explanation`, `planning`, `reviewNotes`, `claimStatus`, `aiStatus`, and `reservation.internalNotes` are **absent/empty** prior to staff approval.
- [ ] **Staff review & approval:** Sign in as the staff account, open `/admin/bookings`, add an internal staff note, review the concept explanation, and click **Goedkeuren**.
- [ ] **Post-approval customer view:** Reload the customer receipt link (or `/my-proposals`). Confirm `requestStatus` is `approved` and `explanation` is now visible, while `planning` and `reservation.internalNotes` remain hidden from the public response.
- [ ] **Unreachable backend error handling:** Temporarily pause Workflow B in n8n (or block `neovenio.app.n8n.cloud` in browser DevTools Network) and submit a request; confirm the UI displays an explicit error banner and **never** fabricates a local demo confirmation.

### 3. `#14` Live concurrency & Data Table checks (`docs/adr/0001-slot-claims.md`)

- [ ] **System `id` & `createdAt` check:** Inspect an execution of Workflow B (`Insert claim` and `Re-read records after claim`) in n8n UI (temporarily enabling execution inspection if needed) to verify `Insert claim` outputs numeric row `id` (if missing, requests fail closed with `503`) and `get` returns `id` plus ISO `createdAt`.
- [ ] **Simultaneous overlapping requests (race check):** With a valid customer Firebase `$ID_TOKEN` and a published `<ROOM_ID>`, fire two overlapping requests in parallel from two terminals (or run two background curls in a local terminal):

```bash
curl -sS -w '\nHTTP %{http_code}\n' -X POST https://neovenio.app.n8n.cloud/webhook/h20/public \
  -H "Authorization: Bearer $ID_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "event-request",
    "requestId": "11111111-1111-4111-8111-111111111111",
    "customerToken": "11111111-1111-4111-8111-11111111111111111111-1111-4111-8111-111111111111",
    "customer": { "fullName": "Race Test A", "email": "race-a@example.test" },
    "config": {
      "name": "Race A",
      "type": "Teambuilding",
      "participants": 20,
      "date": "2027-05-20",
      "startTime": "10:00",
      "endTime": "14:00",
      "selectedRoomId": "<ROOM_ID>"
    }
  }'
```

Submit the second request concurrently with `"requestId": "22222222-2222-4222-8222-222222222222"` and `"customerToken": "22222222-2222-4222-8222-22222222222222222222-2222-4222-8222-222222222222"` for the same room/date/time:

- [ ] Exactly one request returns `HTTP 201` with a receipt and the other returns `HTTP 409` (`Deze datum of tijd overlapt een aanvraag of blokkade.`).
- [ ] `Delete lost claim` removes the losing row by numeric `id`, leaving **zero** `claimStatus: "claiming"` rows behind in `h20_records`.
- [ ] **Stale claim indicator (`Onvolledige aanvraag`):** Confirm a `claiming` row older than 10 minutes (by `createdAt`) displays **Onvolledige aanvraag** in `/admin/bookings` and can be rejected cleanly.
- [ ] **Gemini failure graceful hold (`AI-uitleg ontbreekt`):** Temporarily set an invalid Gemini credential key on Workflow B and submit a non-overlapping request:
  - [ ] Customer still receives `HTTP 201` receipt (`claimStatus: "held"`, `aiStatus: "failed"`).
  - [ ] Staff portal shows **AI-uitleg ontbreekt** and blocks approval (`409`) until staff enter proposal text via **Beoordelen** (`review`), after which restore the valid Gemini credential.
