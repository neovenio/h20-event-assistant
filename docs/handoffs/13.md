# Handoff: #13 Router routes

## What changed

- `src/app/app.routes.ts`: route table. `/`, `/plan` (event builder overlay), `/my-proposals`, `/knowledge`, `/rooms`, `/activities`, `/catering`, `/admin/:section` (9 sections, default `bookings`). Unknown paths redirect to `/`. Routes are component-less: the `App` shell still renders every page and derives the active page from the URL (`tab`/`page`/`adminSection` computeds).
- `src/app/event-assistant/staff-guard.ts`: functional `canActivate` guard. Awaits the Firebase session restore, then allows only `auth.staff() === true` (plus the existing local-demo staff portal, `auth.demoStaff`, only when no n8n backend is configured). Otherwise it redirects to `/` (fragment preserved) and sets `auth.accessDenied`, which makes the shell open the login prompt (or show a "no access" notice when already signed in).
- `AuthService`: new `demoStaff` and `accessDenied` signals. The staff claim is now awaited during `restore()` so a refresh on `/admin` does not race.
- `App`: nav and CTAs use `routerLink` + `routerLinkActive` (desktop and mobile share one nav). All `tab.set(...)` calls navigate instead. The `admin` signal is now computed from `staff || demoStaff`. After a refresh on `/admin` the staff data is loaded (`refreshAdmin`).
- `Admin`: sub-tabs are `routerLink`s. The active section is an input (`section`) fed from the route.
- Receipts: still read from the URL fragment only, now via `router.parseUrl(router.url).fragment`, on any route, and also when the fragment changes after load. The token never moves to path or query. Redirects keep the fragment.
- No `ActiveTab`/`AdminSubTab` unions existed in this repo (tabs were plain strings). `Page`/`AdminSection` are now derived from `PAGE_PATHS`/`ADMIN_SECTIONS`.

## Hosting decision (also in docs/ANGULAR-MIGRATION.md)

All public routes are prerendered (`dist/.../browser/<route>/index.html`). `admin/**` uses `RenderMode.Client`. `firebase.json` has a catch-all rewrite `** -> /index.csr.html` (Firebase serves static files first, so only `/admin/**` and unknown paths hit it). `index.csr.html` is used rather than `index.html` to avoid hydrating the prerendered dashboard markup into another page.
