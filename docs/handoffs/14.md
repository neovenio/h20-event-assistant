# Handoff: #14 Race-safe slot claims

## What changed

- `backend/n8n/code/domain.cjs`: `parseRows` keeps `rowId`/`rowCreatedAt` (Data Table `id`, `createdAt`). New `resolveClaim` (pure), `settleClaim`, `claimStatusOf`/`aiStatusOf`, shared `isActiveBooking`. `event-request` now returns `route: 'claim'` (claim row with `claimStatus: 'claiming'`) instead of going straight to Gemini; a retry that finds a `claiming` row re-verifies (`gemini` or `lost`). `finishGemini` keeps the hold on any AI failure (`aiStatus: 'failed'`, saved `held`, normal receipt); chat still returns 502. `add-block` returns a `claim` route too, with a unique block id. Snapshot adds `claimCreatedAt` for `claiming` bookings. `review` sets `aiStatus: 'ok'`; approving a failed-AI booking without text is refused with 409. `publicBooking` strips `claimStatus`/`aiStatus`.
- `backend/n8n/generate-workflows.cjs` (workflows B and C regenerated): Route request -> Needs claim -> Write claim -> Insert claim -> Re-read records after claim -> Settle claim -> (B: Needs Gemini / C: Result). Result -> Needs delete -> Delete lost claim (`deleteRows` by `recordId`) -> After lost claim (409) -> Respond.
- `backend/n8n/code/notifications.cjs`: skips `claiming` bookings (no receipt mail for a claim that may still lose).
- Staff UI: `admin.html`/`admin.ts` show "AI-uitleg ontbreekt" and "Onvolledige aanvraag" (claiming and older than 10 minutes by `claimCreatedAt`); `Booking` model gets optional `claimStatus`, `claimCreatedAt`, `aiStatus`. Test: `components/admin.spec.ts`.
- Docs: `docs/adr/0001-slot-claims.md`, n8n README "Prototype limitations" updated.

## How to verify

`node --test backend/n8n/tests/domain.test.cjs`, `npm run test:ci`, `npm run build`, `npm run lint`, `npm run format:check`. The interleaving tests give each request a snapshot containing both inserted claims (ids assigned like the Data Table would) and assert the lowest id wins in either evaluation order.

## Notes and follow-ups

- Not run against live n8n (#7): confirm the Data Table `insert` node, `get` returning `id`/`createdAt`, and `deleteRows` filtering on `recordId`.
- Staff cannot yet see stale claims on the calendar/blocks tabs; a stuck `claiming` block is removed with `delete-block`.
- A reject of a `claiming` row while its request is still in flight would be overwritten by the final upsert (only possible inside the 10 minute window; accepted).
- Rows lacking a `rowId` (tests, pre-capture data) rank first.
