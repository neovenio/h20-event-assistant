# Handoff: #14 Race-safe slot claims

## What changed

- `backend/n8n/code/domain.cjs`
  - `parseRows` keeps the Data Table system columns as `rowId` / `rowCreatedAt`.
  - New pure `resolveClaim(rows, claim) -> { won, winnerId }` (lowest row id among overlapping active bookings and blocks wins) and `settleClaim(context, insertedId, rows)`.
  - `event-request` now returns `route: 'claim'` (claim row with `claimStatus: 'claiming'`, plus `next` = the Gemini route). A retry that finds a `claiming` row re-verifies and returns `gemini` (won) or `release` (lost, 409). A `held` or legacy row returns the receipt as before.
  - `finishGemini` marks the booking `held` + `aiStatus: 'ok'`; any 502-class AI failure degrades to a saved `held` booking with `aiStatus: 'failed'` and a normal receipt (chat still returns 502).
  - `add-block` returns a `claim` route the same way (`next` = the held block save). Block ids get a random suffix.
  - `publicBooking` strips `claimStatus` and `aiStatus`. `review` clears `aiStatus: 'failed'`. Approval is refused for `claiming` bookings and bookings without explanation.
- `backend/n8n/generate-workflows.cjs`: B and C get Needs claim, Claim insert (Data Table `insert`), Read after claim, Resolve claim, Request context, Needs release, Release claim (Data Table `deleteRows` by `id`), After release. Claim insert happens before Gemini.
- Regenerated `backend/n8n/workflows/B-*.json` and `C-*.json` (A and D unchanged).
- Staff UI: `admin.ts`/`admin.html` show "AI-uitleg ontbreekt" and "Onvolledige aanvraag" (claiming, older than 10 minutes by `reservation.createdAt`, not rejected). `Booking` type got optional `claimStatus`/`aiStatus`.
- Tests: `backend/n8n/tests/domain.test.cjs` (in-memory Data Table simulating interleaving; existing tests adapted to the claim route; workflow wiring assertions) and `src/app/event-assistant/components/admin.spec.ts`.
- Docs: `docs/adr/0001-slot-claims.md`, `backend/n8n/README.md` (new "Slot claims" section, limitation updated).

## IMPORTANT: re-import in n8n

Workflows **B and C must be re-imported** in n8n (and the Data Table selected in the new Insert, Read after claim and Release claim nodes, plus the Gemini credential in B). Not done here; no live n8n was contacted.

## Notes and follow-ups

- Unverified against live n8n (#7): that Data Table `insert` returns `id`, that `deleteRows` filters on the `id` system column, and real concurrent behaviour.
- Decision not in the brief: staff cannot approve a booking without explanation (needed because a failed-AI hold has none) or one still `claiming`.
- Block ids now include a random suffix (a deleted block keeps its row, so a reused recordId would collide).
- The stale check uses `reservation.createdAt` (set when the claim is created) rather than the row `createdAt`, which the snapshot does not expose.
