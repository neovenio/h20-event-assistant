## 3. Pre-go-live automated validation commands

Run each command separately on the release candidate before merging to `main`:

```bash
node scripts/check-requirements.cjs
```

```bash
node --test backend/n8n/tests/domain.test.cjs
```

```bash
npm run format:check
```

```bash
npm run lint
```

```bash
npm run test:ci
```

```bash
npm run build
```

All six commands must exit `0` with no bundle-budget warnings, and `config/runtime/prod.json` must contain the real `h20-event-assistant-prod` Firebase web config and `https://neovenio.app.n8n.cloud/webhook/h20-prod`.

## 4. Production smoke test & privacy sign-off checklist (post-deploy on `https://h20-event-assistant-prod.web.app`)

- [ ] **Runtime config check:** Fetch `https://h20-event-assistant-prod.web.app/h20-runtime.json` and confirm `firebase.projectId === "h20-event-assistant-prod"`, `n8nWebhookBaseUrl === "https://neovenio.app.n8n.cloud/webhook/h20-prod"`, and no secret keys exist.
- [ ] **Public routes & deep links (`#13`):** Cold-load `/`, `/plan`, `/rooms`, `/activities`, `/catering`, `/knowledge`, and `/admin/bookings` (confirming unauthenticated `/admin/bookings` redirects to `/` and prompts sign-in).
- [ ] **Catalogue integrity (`#8`):** Confirm only staff-curated H20 rooms/activities/catering appear, no duplicate stadium capacity exists, and unconfirmed tariffs show **op aanvraag**.
- [ ] **End-to-end customer → staff → email → PDF flow:**
  1. Sign up as a test customer on `h20-event-assistant-prod.web.app` and submit a concept event request (including at least one `op aanvraag` item and a budget ceiling to confirm budget/op-aanvraag warnings).
  2. Verify receipt email arrives via `[PROD]` Workflow D with a link to `https://h20-event-assistant-prod.web.app/#request=...` and that unpublished AI explanation and internal notes are hidden.
  3. Sign in with an H20 `staff: true` account, review the generated explanation/planning in `/admin/bookings`, and approve the concept.
  4. Verify approval email arrives via `[PROD]` Workflow D, customer can view the approved concept explanation, and PDF offer download (`#12`) produces a clean, readable concept offer clearly marked as non-binding.
  5. Clean up / reject the smoke-test booking so real room availability is unaffected.
- [ ] **Privacy & n8n execution retention sign-off:**
  - Confirm `saveDataSuccessExecution: "none"`, `saveDataErrorExecution: "none"`, and `saveManualExecutions: false` are active on `[PROD]` Workflows A–D in `neovenio.app.n8n.cloud`.
  - Confirm n8n workspace execution-retention policy and workspace member access are restricted to authorized administrators, and that customer PII (`email`, `phone`, `billingAddress`) is never sent in `Gemini` prompts or logged in browser console output.
