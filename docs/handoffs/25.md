# #25 Keep edit target through booking form; apply assistant plans to open builder

## What changed

- `src/app/app.ts` / `app.html`: `startBooking` remembers the edit target; new `dismissBooking()` reopens the builder with the same config and proposal id. New `assistantPlan()` / `confirmPlan()` / `cancelPlan()` handle assistant `build` events. A plan applied to an open builder clears the edit target (always a new concept). If the builder has unsaved changes an in-app `app-modal` ("Je huidige plan vervangen?") asks first. With no open builder the old `openBuilder(plan)` path is used. `build(null)` ("Zelf samenstellen") with an open builder only closes the chat.
- `event-builder.ts`: `hasUnsavedChanges()` (config vs last applied initial) and `replaceConfig()` (copy, reset baseline, step 1).
- Tests in `src/app/app.routes.spec.ts` cover every acceptance criterion.

## Verify

`npm run test:ci`, `npm run lint`, `npm run format:check` (all pass).

## Follow-ups

- None. (The booking round trip now preserves the unsaved-changes baseline via the `baseline` input on `EventBuilder`; `pendingPlan` is cleared when leaving /plan.)
